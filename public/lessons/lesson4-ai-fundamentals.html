Part 1: What Is an LLM?

You've been using AI through Cursor — typing questions in chat, getting code suggestions. But what exactly is the AI behind it?

The Restaurant Analogy (continued)

Remember our restaurant from Lesson 3? React is the decorator, Apollo is the waiter, the backend is the kitchen. Now imagine we hire a new staff member: a brilliant consultant who has read every cookbook, every restaurant review, and every food blog ever written.

This consultant doesn't actually know anything — it has never cooked a dish or tasted food. But it has seen so many examples of cooking that it can predict with incredible accuracy what the next ingredient should be in any recipe, what the answer to any food question would be, and even write a new recipe from scratch.

That consultant is an LLM — a Large Language Model.

How It Actually Works (simplified)

An LLM is a neural network trained on massive amounts of text. Here's the core idea:

1 Training
The model reads billions of pages of text — books, websites, code, conversations — and learns patterns. Not facts, not rules, but patterns of how words and ideas follow each other.
2 Prediction
When you ask a question, the model doesn't "look up" an answer. It predicts the most likely next word, then the next, then the next — generating a response one token at a time.
3 Fine-tuning
After initial training, the model is refined to be helpful, honest, and harmless. This is why it answers questions instead of just completing random text.

Key insight: An LLM doesn't "understand" things the way humans do. It's extremely good at recognizing and continuing patterns. When you ask "What is React?", it generates an answer because it has seen thousands of explanations of React and predicts what a good answer looks like. The result is impressively useful — but it's pattern matching, not understanding.

What Is a Token?

LLMs don't read words — they read tokens. A token is roughly 3/4 of a word in English. Some examples:

Text Tokens Count
Hello "Hello" 1
Hello world "Hello" + " world" 2
function getData() "function" + " get" + "Data" + "()" 4
A 500-word email — ~375 tokens

Why does this matter? Because everything has a cost per token, and there's a limit to how many tokens the model can process at once. That limit is called the context window.

🤖
Developer: "Can you read my entire codebase?"
LLM: "Sure! Send it over."
Developer: *sends 2 million lines of code*
LLM: "I said I can read, not that I have infinite memory."
Context windows are big, but not that big. Yet.

Part 2: The Context Window

The context window is the most important concept you need to understand about LLMs. It determines what the model can "see" and work with at any given moment.

The Desk Analogy

Imagine the LLM is a brilliant analyst sitting at a desk. The context window is the size of that desk.

Everything the analyst needs to work with must fit on the desk: your question, the relevant code files, the conversation history, any instructions. If the desk is too small, some papers fall off and the analyst forgets about them.

A bigger desk = the analyst can juggle more information at once. A smaller desk = the analyst has to work with less context and might miss important details.

Context Window Sizes

Different models have different desk sizes:

Model Context Window Roughly Equals
GPT-3.5 4K tokens ~3,000 words (a short essay)
GPT-4 128K tokens ~96,000 words (a novel)
Claude Sonnet 4.6 200K tokens ~150,000 words (two novels)
Claude Opus 4.6 200K–1M tokens ~750,000 words (an encyclopedia)

What Goes Into the Context Window?

Every time you chat with an AI, the context window is filled with several things:

The context window is shared between system prompt, history, files, and your question

Why this matters practically: If your conversation is too long, the model starts to "forget" earlier messages. If you attach too many files, there's less room for reasoning. This is why tools like Cursor are smart about which files to include — they pick only the most relevant ones to fit within the context window.

Practical Tips for Working With Context

1 Start fresh conversations for new topics
Don't keep using the same chat for hours. When you switch tasks, start a new conversation so the context isn't polluted with irrelevant history.
2 Be specific about what you need
Instead of "fix this file", say "fix the authentication check on line 42 of login.tsx". The more precise you are, the less context the model wastes figuring out what you mean.
3 Include only relevant files
Don't drag your entire project into the chat. Include only the files that are relevant to your question. Cursor does this automatically, but manual control helps.

Part 3: Chatbot vs Agent

You've probably used ChatGPT, Claude, or the chat in Cursor. These are all chatbots. But recently you've heard the word "agent" everywhere. What's the difference?

The Restaurant Analogy (again)

A chatbot is like a restaurant consultant who sits at a table and answers your questions. "What wine goes with salmon?" — they give you a great answer. "How should I reorganize the kitchen?" — another great answer. But they never leave their chair. They can only talk.

An agent is like a consultant who can actually get up and do things. You say "reorganize the kitchen" and they walk in, move the equipment, rearrange the shelves, test the new layout, and come back with a report. They can use tools, make decisions, and take multiple steps to complete a task.

Feature Chatbot Agent
Input Text question Goal / task description
Output Text response Actions + results
Tools None — can only generate text Can read files, run commands, search the web, edit code
Multi-step? One question → one answer Plans steps, executes them, adapts based on results
Memory Only within the current conversation Can save notes for future conversations
Example ChatGPT web chat Claude Code, Cursor Agent mode

The Agent Loop

An agent works in a loop: Think → Act → Observe → Repeat.

An agent autonomously loops through thinking, acting, and observing

Real-world example: When you use Cursor in Agent mode (Cmd+I), it doesn't just answer — it reads your files, searches for relevant code, writes changes, and even runs your tests. That's the agent loop in action. Claude Code works the same way in the terminal.

🧠
User: "Can you fix this bug?"
Chatbot: "Sure! Here's how you could fix it: [explanation]"
Agent: *reads 15 files, finds the bug, edits 3 files, runs the tests* "Done. Here's what I changed and why."
Same question, very different energy.

Part 4: MCP — The Tool Belt

So agents can "do things." But how exactly does an agent interact with the outside world — read files, search the web, create GitHub pull requests? The answer is MCP — Model Context Protocol.

What Is MCP?

Back to our restaurant. The consultant (LLM) is brilliant, but can they personally chop onions, check the inventory system, or call the supplier? No. They need tools.

MCP is like a universal tool belt. It's a standard protocol that lets AI agents connect to external services and tools in a consistent way. Instead of every tool having its own unique integration, MCP provides one standard way for AI to use any tool.

How MCP Works

MCP is a standard "USB port" — any tool that speaks MCP can plug into any AI agent

Why MCP Matters

Before MCP, every AI tool had to build custom integrations for each service. Want GitHub? Custom code. Want Figma? More custom code. Want a browser? Even more custom code.

MCP solves this with a standard protocol, much like USB solved the "every device needs a different cable" problem:

🔌
Before MCP
Every cable is different
Each AI app builds custom integrations. If you switch from GPT to Claude, all integrations break.
🔌
With MCP
One standard port
Build the tool once as an MCP server. Any AI that speaks MCP can use it. Switch AI models freely.

MCP Tools We Use

Here are some MCP servers that are connected to our AI tools right now:

MCP Server What It Does Example Use
GitHub Create PRs, read issues, review code "Create a PR for this branch"
Playwright Navigate websites, take screenshots, click buttons "Open staging and screenshot the login page"
Vercel Deploy apps, check build logs, manage environments "Deploy this branch to preview"
Figma Read design files, get component specs "What are the colors in this design?"
Context7 Look up library documentation "How does React useEffect work?"

In practice: When you use Claude Code or Cursor's agent mode, MCP tools work behind the scenes. You just say what you want — "create a GitHub issue for this bug" — and the agent uses the right MCP tool automatically. You don't need to know the technical details of MCP to benefit from it.

Part 5: Skills & Subagents

Now we get to the most powerful part: how agents can be extended with skills and subagents to handle complex, multi-step workflows.

What Are Skills?

A skill is like a recipe card for the agent. Instead of explaining a complex task from scratch every time, you write it down once as a skill, and the agent can follow it whenever needed.

For example: instead of typing "Read the git log, look at all changes, write a good commit message, and create a commit" every time, you just type /commit and the skill handles all of that automatically.

Skills are essentially reusable prompts with instructions that tell the agent what to do. They can be simple (like formatting a commit message) or complex (like running a full code review workflow).

Example Skills We Use

📝
/commit
Analyze changes, write a commit message, create a commit
🔍
/review-pr
Review a Pull Request and leave detailed feedback
🎯
/simplify
Review changed code for quality, then fix any issues
🛠
/bug-tracing
Systematic bug diagnosis with hypothesis-driven debugging
📋
/prd-creation
Create a Product Requirements Document for a new feature

What Are Subagents?

Imagine the main consultant (agent) gets a really big task: "redesign the entire menu." Instead of doing everything alone, they call in specialist consultants:

  • A food critic to analyze the current menu
  • A chef to design new dishes
  • A designer to create the menu layout
  • A financial analyst to check the pricing

Each specialist works on their part independently and reports back. The main consultant coordinates everything.

That's exactly what subagents do. The main agent spawns specialized sub-agents that work in parallel on different parts of the task.

Types of Subagents

Different subagent types are designed for different specialties:

Subagent Type Specialty When to Use
code-architect Full-stack development Implementing features, writing code
ux-designer UI/UX design Designing screens, prototyping
db-optimiser Database performance Schema design, query optimization
security-auditor Application security Finding vulnerabilities, reviewing auth
code-tester Automated testing Writing tests, validating behavior
researcher Deep web research Market analysis, finding solutions

Why subagents? Two reasons. First, parallelism — the main agent can launch 5 subagents at once and get results faster. Second, context protection — each subagent has its own context window. The main agent's context doesn't get cluttered with search results and intermediate work.

How It All Fits Together

The full AI stack: You give a task → Agent thinks and coordinates → Skills provide recipes → MCP connects to tools → Subagents parallelize work

Part 6: Cursor's Two Modes — Theory Meets Practice

You already know Cursor from Lesson 3. Now that you understand chatbots and agents, let's look at what's actually happening when you use Cursor's two modes.

💬 Chat Mode (Cmd+L) = Chatbot
Text in, text out. You ask a question — it gives an answer based on the files currently open. Good for learning, exploring, and asking questions. The context window includes your open files and conversation history.
🤖 Agent Mode (Cmd+I) = Agent
Agent behavior — it reads files on its own, searches the codebase, writes code, and can even run terminal commands. Uses the agent loop (think → act → observe). Can edit multiple files in one go without you opening them.

When to Use Which?

Situation Use Chat (Cmd+L) Use Agent (Cmd+I)
"What does this function do?" ✓
"Explain this error message" ✓
"Fix the bug in this component" ✓
"Refactor this across 5 files" ✓
"Add a new feature with tests" ✓
"What is GraphQL?" ✓

Rule of thumb: Use Chat when you want to learn something. Use Agent when you want to do something. Chat is the consultant answering questions at the table. Agent is the consultant who gets up and reorganizes the kitchen.

MCP in Practice: Connecting Claude to Notion

Enough theory — let's see MCP in action. We'll connect Claude Desktop (a free app) to Notion, so Claude can read and search your actual Notion pages.

What is Claude Desktop? It's a free desktop app from Anthropic (the company that makes Claude). Think of it as a smarter version of ChatGPT — but one that can connect to your tools via MCP. You can download it at claude.ai/download.

Step-by-step: Connect Notion MCP

1 Install Claude Desktop
Download and install from claude.ai/download. Sign in with your account (you need a Pro, Max, Team, or Enterprise plan for MCP connectors).
2 Open Settings → Connectors
In Claude Desktop, go to Settings → Connectors. This is where all MCP connections are configured.
3 Add the Notion connector
Click Add Connector and enter the URL: https://mcp.notion.com/mcp. Then complete the OAuth flow — Notion will ask you to grant access to your workspace.
4 Chat about your Notion pages
Now you can ask Claude things like: "Find the page about onboarding in my Notion" or "Summarize the meeting notes from last week." Claude uses the Notion MCP to search and read your actual pages.

This is MCP in action! Remember the diagram from Part 4? Claude (the AI Agent) sends a request through MCP to the Notion Server, which searches your workspace and returns the data. Claude then uses that data to answer your question. You just connected a "USB cable" between Claude and Notion.

Other Useful MCP Connectors

Before MCP: "Let me copy this Jira ticket, paste it into Claude, then copy the Notion page, paste that too..."

Same AI brain, but now it can reach the data itself.

Summary

Let's recap the key concepts from this lesson:

LLM A neural network trained on text that predicts the next token. Not "understanding" — but incredibly useful pattern matching.
Context Window The "desk" where everything must fit: your question, code files, conversation history, system instructions.
Chatbot Text in, text out. Can only answer questions. No tools, no actions, no multi-step reasoning.
Agent Think → Act → Observe loop. Can use tools, make decisions, and complete complex tasks autonomously.
MCP Model Context Protocol — a "USB standard" that lets AI connect to any external tool: GitHub, Figma, browsers, databases.
Skills Reusable "recipe cards" for the agent. Type /commit and the agent knows exactly what to do.
Subagents Specialized mini-agents that run in parallel. Each has its own context window and expertise.
Cursor Modes Chat (Cmd+L) = chatbot for questions. Agent (Cmd+I) = agent for actions. Same AI, different capabilities.

The big picture: AI is not magic — it's a tool with clear strengths and limitations. The LLM is the brain. The agent loop gives it hands. MCP connects it to the world. Skills give it recipes. Subagents let it delegate. Understanding these pieces helps you use AI more effectively and debug problems when they arise.
