Part 1: What Is an API?

Before diving deeper into MCP, let's understand the foundation it's built on: APIs. Don't worry — no coding required. Just our old friend, the restaurant.

The Restaurant Analogy (continued)

Remember our restaurant from Lessons 3 and 4? React decorates the dining room, Apollo is the waiter, the backend is the kitchen, and our brilliant LLM consultant sits at a corner table, ready to help.

Now imagine you want sushi from the Japanese place next door. You can't just walk into their kitchen — you're a stranger there. Instead, they have a waiter with a specific menu and ordering rules: «Write your order on this card, in this format, and hand it to me.»

That waiter + menu + ordering rules = API (Application Programming Interface). It's a defined contract for how one program can talk to another.

In plain English: An API is a doorway with a bouncer. The bouncer says: «I accept requests in this format, and I'll give you answers in that format. Follow the rules, and we're good.»

API in Real Life

Every time software communicates with other software, it uses an API:

📱
Mobile App
Uses the Fohlio API to load your projects and products
🌐
Website
Uses the Stripe API to process payments
🤖
Claude
Uses the Notion API to read your pages
📊
Slack Bot
Uses the Slack API to send messages in channels

Key idea: An API is a contract. It says: «Send me a request in this exact format, and I'll send you a response in this exact format.» Without APIs, programs would have no way to talk to each other.

The Problem with APIs (for AI)

APIs are great for developers. But there's a catch when AI needs to use them:

💥
Every API Is Different
Notion API works differently from Jira API, which works differently from GitHub API. It's like every restaurant in the food court has a different language on their menu.
🔧
Custom Code for Each
To connect AI to each tool, someone has to write custom integration code. Imagine hiring a separate translator for each restaurant. Expensive!
🍔
You: «I want sushi, pizza, and tacos.»
Without API: You walk into 3 kitchens, get kicked out of 2.
With API: You call 3 waiters, fill out 3 different order forms in 3 different formats.
With MCP: You tell one assistant what you want, and they handle all 3 waiters for you.
MCP is the personal food concierge you didn't know you needed.

This is exactly the problem MCP solves. Let's see how.

Part 2: API vs MCP — What's the Difference?

Now for the most important concept in this lesson. If you remember one thing, make it this.

The USB Analogy (revisited)

Imagine a world before USB. Your printer needs a parallel port cable. Your camera needs FireWire. Your phone needs a 30-pin connector. Your mouse needs PS/2. You open your drawer and it looks like a snake pit of different cables.

Then USB arrived: one standard connector for everything. Any device, any computer — same plug. The drawer went from chaos to one cable that rules them all.

API = the snake-pit era. Each tool has its own cable, its own rules. MCP = USB — one standard protocol that works everywhere, for everyone.

Fun fact: MCP was created by Anthropic in November 2024. By late 2025, it was donated to the Agentic AI Foundation under the Linux Foundation, with OpenAI, Google, Microsoft, AWS, and GitHub as supporters. It's becoming the actual industry standard — not just an analogy.
Aspect Traditional API MCP
Format Each API has its own format (REST, GraphQL, etc.) One standard format for all tools
Authentication Different for each service (API keys, OAuth, tokens) Standardized — usually one-time OAuth in the app
Integration Effort Developer writes custom code per tool Install an MCP server — AI connects instantly
Who Can Set Up Developers only Anyone (point-and-click or paste a URL)
Discovery AI doesn't know what tools are available AI automatically sees all connected tools
Best Analogy Different cable for every device USB — one connector for everything
Left: each tool needs custom integration. Right: MCP provides one standard interface for all tools.

Why this matters for you: Without MCP, only developers could connect AI to tools. With MCP, anyone can do it — just paste a URL or click a button. That's the revolution.

Part 3: Adding MCP Servers to Claude Desktop

Imagine this moment: you open Claude Desktop, type «What tickets do I have in Jira?» and Claude actually checks Jira and lists your tickets. No copy-pasting. No switching tabs. No «here's how you could find out...» — it just does it.

That's what we're setting up right now. In 5 minutes, you'll have a Claude that can reach into your real work tools.

Claude Desktop supports two ways to add MCP servers: Connectors (built-in, easy) and manual configuration (JSON file, flexible). Let's learn both.

Method 1: Connectors (the easy way)

Connectors are pre-built MCP integrations — like pre-configured USB cables. You just plug them in: paste a URL, click Allow, done.

1 Open Claude Desktop Settings
Click on your profile icon in the bottom left → Settings. Or use the keyboard shortcut.
2 Go to the «Connectors» tab
In the Settings panel, find and click Connectors (or MCP depending on your version). You'll see a list of already connected services (if any).
3 Click «Add Connector»
A dialog will appear asking for a URL. Enter the MCP URL for the service you want to connect. For example:
https://mcp.notion.com/mcp for Notion.
4 Authenticate via OAuth
The service (Notion, Jira, etc.) will open a browser window asking you to grant access. Click «Allow». This is a one-time step.
5 Start using it!
Now when you chat with Claude, it can access that service. Try: «Find the onboarding page in my Notion» or «What are my open Jira tickets?»

Method 2: Manual Configuration (JSON file)

Some MCP servers aren't available as built-in connectors. In that case, you can add them manually through a JSON config file.

1 Open the config file
In Claude Desktop: Settings (gear icon) → Developer tab → Edit Config button.
Or open the file directly:
On macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
On Windows: %APPDATA%\Claude\claude_desktop_config.json
2 Add the MCP server entry
Add your MCP server to the mcpServers section. Here's a real example with Notion and HubSpot:
{
  "mcpServers": {
    "notionApi": {
      "command": "npx",
      "args": ["-y", "@notionhq/notion-mcp-server"],
      "env": {
        "NOTION_TOKEN": "ntn_your_token_here"
      }
    },
    "HubspotMCP": {
      "command": "npx",
      "args": ["-y", "@hubspot/mcp-server"],
      "env": {
        "PRIVATE_APP_ACCESS_TOKEN": "your_hubspot_token"
      }
    }
  }
}

You can add multiple servers at once! Just add more entries inside mcpServers. Each one gets its own name, command, and credentials. Claude will see all of them.

3 Restart Claude Desktop
Close and reopen the app. In a new chat, click Search and Tools — you'll see your connected servers and their tools listed. Enable them if needed.

When to use which method? Use Connectors (Method 1) for popular services — it's easier and handles auth automatically. Use Manual config (Method 2) for custom or community MCP servers that aren't in the built-in list.

Part 4: Manus — Another AI Agent Platform

What is Manus?

Back to our restaurant. Claude Desktop is like sitting with the brilliant consultant at the same table. You talk, they answer, you go back and forth. Great for collaboration.

Manus is different. Manus is like giving the consultant a task and saying: «Go figure this out. Come back when you're done.» The consultant leaves, visits 15 restaurants, talks to 30 people, creates a spreadsheet, and emails you the result 20 minutes later.

Manus is an autonomous AI agent platform (B2B SaaS) that launched in early 2025. It runs entirely in the cloud — you don't install anything on your computer. It has its own browser, file system, and tools in a cloud sandbox. You describe a task, Manus plans and executes it, and delivers the output. You can even close your laptop — Manus keeps working.

Key distinction: Anthropic (the company behind Claude) is an AI model provider — they build the AI brain and offer it through various interfaces (Claude Desktop, API, Claude Code). Manus is a B2B SaaS product — a platform that uses AI models (including Claude's!) to automate business tasks end-to-end. Claude Desktop = working together on your computer. Manus = delegating to a cloud agent and checking the result later.

Why this matters: Claude Desktop can't do this — it's a desktop app that requires your computer to be on and the app to be open. Manus runs in the cloud, so scheduled tasks execute regardless of whether you're at your desk. This is the fundamental advantage of a cloud-based agent platform over a local desktop tool.

Manus has built-in connectors for popular services, plus support for custom MCP servers.

Built-in connectors (the easy path)

These are available out of the box via OAuth — no JSON config needed:

1 Open Manus Settings
Log into manus.im, go to your profile → Settings → Integrations.
2 Choose a connector
Click on the service you want (Gmail, Notion, HubSpot, etc.) and complete the OAuth flow — log into the service and grant Manus access.
3 Use it in your tasks
Just mention the service in your prompt. Manus automatically picks the right connector.
Example: «Check my Google Calendar for this week and create a summary in Notion.»

Custom MCP servers (for everything else)

1 Go to Settings → Integrations → Custom MCP Servers
Click Add Server and enter the server details.
2 Configure the server
Provide:
• Server name — a descriptive label (e.g., «Internal CRM»)
• Server URL — the HTTPS endpoint of your MCP server
• Authentication — API key, Bearer token, or other credentials
3 Verify and use
Manus will check the connection and discover available tools. Start using them in your tasks.

Key difference: In Claude Desktop, MCP tools are available in your chat — on your computer, while you are working. In Manus, MCP tools are available for the agent's autonomous cloud work — it can run tasks on a schedule, even at 3 AM. Claude is a conversation partner with superpowers (model provider). Manus is a cloud employee you send on a mission (B2B SaaS).
